# გასაუბრების წარდგენის გზამკვლევი

ეს არის მოთხოვნებზე მორგებული სასწავლო დემო. ინტერფეისი ადაპტირებულია არსებული Insurance Group-იდან; ახალ რეპოზიტორიაში ბიზნეს API და მონაცემთა შენახვა C#/EF Core-ზეა გადატანილი. რეალური დაზღვევა და გადახდა არ ხდება. წყაროს მითითება: [UPSTREAM.md](../UPSTREAM.md).

## 6–8 წუთის დემო

1. **იდეა და სტეკი:** Travel-ის შეთავაზება → შეძენის სიმულაცია → პოლისი → ზარალის განაცხადი. React/TypeScript/Tailwind ფრონტი, ASP.NET Core API, PostgreSQL და EF Core. სხვა პროდუქტები მხოლოდ წინასწარი ფორმებია და მათი შეძენა დასრულებულ ფუნქციად არ უნდა წარადგინო.
2. **ავტორიზაცია:** გამოგონილი მომხმარებლით რეგისტრაცია, გამოსვლა, შესვლა. აჩვენე ცარიელი ანგარიში და ვალიდაცია. პაროლის ჰეშირებას Identity აკეთებს; ფრონტში პაროლი მხოლოდ მიმდინარე ფორმაშია.
3. **მთავარი გზა:** Travel-ის მონაცემები, შედარება, მგზავრები, მიმოხილვა და სატესტო გადახდა. აჩვენე მიღებული DEMO პოლისი და კერძო PDF. თანხა რეალურად არ ჩამოიჭრება.
4. **CRUD:** შექმენი გამოგონილი განაცხადის მონახაზი, გახსენი სიიდან, შეცვალე და შეინახე. მხოლოდ ამ საცდელი მონახაზის წაშლა აჩვენე დადასტურების დიალოგით. გაგზავნილი განაცხადის წაშლა განზრახ აკრძალულია.
5. **მდგომარეობები:** გაგზავნილ საცდელ განაცხადზე ოპერატორის დამატებითი ინფორმაციის მოთხოვნა → მომხმარებლის შესწორება → ხელახალი გაგზავნა → ისტორია. „გაგზავნილია“ არ ნიშნავს „დაკმაყოფილებულია“ ან „გადახდილია“.
6. **კოდი და შეზღუდვები:** გახსენი ქვემოთ ჩამოთვლილი 2–3 ფაილი. განმარტე ერთი მოთხოვნის სრული გზა და ownership შემოწმება. Gemini ადგილობრივად კონფიგურირებულია: საჯარო ვიჯეტი ანგარიშის გარეშე პასუხობს, ხოლო სრული ჩატის გვერდზე გამოგონილი პოლისის დაფარვა ცალკე თანხმობით შეგიძლია გააზიარო. გასაღების გარეშე unavailable მდგომარეობა ნორმალურია, რადგან ჩატბოტი დამატებითია.

გამოიყენე მხოლოდ გამოგონილი ჩანაწერები. ოპერატორის პაროლი პირად ადგილობრივ კონფიგურაციაშია; არ აჩვენო `.env`, პაროლები ან API key ეკრანზე/რეპოზიტორიაში.

## კითხვები, რომლებზეც საკუთარი სიტყვებით უნდა უპასუხო

| კითხვა | კოდის ადგილი და ძირითადი ახსნა |
| --- | --- |
| როგორ უკავშირდება React ბექენდს? | `frontend/src/lib/client.ts` → same-origin `/api/v1` → `frontend/next.config.ts` forwarding → C# feature endpoint. Next ბიზნეს ოპერაციებს არ ინახავს და Supabase fallback არ აქვს. |
| რატომ Next.js, თუ React ითხოვეს? | Next არის React-ის ჩარჩო; TypeScript კომპონენტები და Tailwind/CSS ფრონტშია. დავალება Next-ს არ კრძალავს. ბიზნეს API მაინც სავალდებულო ASP.NET Core-ზეა. |
| სად და როგორ ინახება პაროლი? | `backend/Program.cs` Identity კონფიგურაცია; `backend/Features/AuthEndpoints.cs` UserManager/SignInManager. ინახება Identity-ის ჰეში, არა ღია პაროლი ან თვითნაკეთი ფრონტის ჰეში. სესია HttpOnly cookie-ით იმართება. |
| სხვა მომხმარებლის ID რომ ჩავწერო? | `backend/Infrastructure/ApiInfrastructure.cs` და feature სერვისების owner-filtered მოთხოვნები. ფაილიც ownership შემოწმების შემდეგ ბრუნდება. კონტაქტის email ანგარიშზე წვდომას არ გასცემს. იხილე A/B შემოწმებები `backend/scripts/smoke.mjs`-ში. |
| სად არის CRUD? | `backend/Features/ClaimEndpoints.cs`: POST/GET/PATCH/DELETE. Delete მხოლოდ მონახაზისთვისაა. ცვლილება/წაშლა შემოწმებულ ვერსიას იყენებს; მოძველებული ვერსია აბრუნებს409-ს. |
| რაში გჭირდება EF Core და მიგრაცია? | `backend/Domain/Entities.cs`, `backend/Infrastructure/InsuranceDbContext.cs`, `backend/Migrations`. Foreign key/unique constraint-ები ინახავს კავშირებსა და ინვარიანტებს. ახალი გარემო იწყება checked-in მიგრაციებით და არა არსებული ბაზის ასლით. |
| რატომ არის ზოგი მონაცემი JSONB? | შეძენილი ფასის/დაფარვის უცვლელი snapshot-ისთვის. მომხმარებლები, ownership, მგზავრები, განაცხადები, ფაილების მეტამონაცემები და ისტორია რელაციურია. |
| ორჯერ დაჭერამ მეორე პოლისი რომ არ შექმნას? | `backend/Features/CheckoutEndpoints.cs`, DB uniqueness და ტრანზაქცია. უცნობი შედეგი ჯერ მოწმდება; browser callback დაზღვევის გაცემის მტკიცებულება არ არის. მცირე დემოში advisory lock აწყობს ცვლილებებს, მაგრამ ზღუდავს write throughput-ს. |
| როგორ იმართება შეცდომა? | `backend/Infrastructure/ApiInfrastructure.cs` აწარმოებს სტატუსს/კოდს; ფრონტი ლოკალიზებულ შეტყობინებას, field error-ს, retry-ს ან ცარიელ შედეგს აჩვენებს. არასაიმედო პასუხის შემდეგ მნიშვნელოვანი ქმედება ავტომატურად არ მეორდება. |
| რა არ არის დასრულებული? | რეალური პროვაიდერი/Flitt, Health-ის შეძენა, native აპები, production email/reset და ოპერაციული ინფრასტრუქტურა. Gemini-ის რამდენიმე რეალური პასუხი შემოწმებულია, თუმცა პასუხების უტყუარობა გარანტირებული არ არის და ახალი გარემო საკუთარ კერძო key-ს მოითხოვს. ეს სავალდებულო დავალების მიღმაა. |

ეს გზამკვლევი ახსნის შემცვლელი არ არის: წარდგენამდე თავად გაიარე ერთი გზა და წაიკითხე დასახელებული მეთოდები. ინტერვიუზე გამართულად უნდა ახსნა შენს მიერ წარმოდგენილი კოდი და გამოყენებული არსებული ნამუშევარიც.
